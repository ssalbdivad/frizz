## From the composer

Browse your repo's issues and pull requests from the prompt box, select any number of them, and each becomes its own thread.

<Shot src="/img/github.png" width={1600} height={1027} alt="The GitHub picker open over the prompt box, listing open issues with three of them checked." />

Each item is dispatched with one prompt, which you can edit from the picker's gear. The default has the worker read the whole thread and branch: a reproduction and fix plan for a bug, a plan for a feature, a review for a PR.

## Read, never write

Workers read issues, diffs and CI on their own, through the `gh` you are signed in to. A worker never comments, labels, closes, merges or opens a pull request unless you ask it to.

## Watchers

A worker waiting on a build, a review or a reporter's reply doesn't hand the thread back to be told "keep going." It registers a watch and rests, out of the queue, until something happens:

- **A pull request** wakes it when CI goes green or red, on a review, approval or comment, when a label moves, when it starts conflicting with its base, and when CI is waiting for a maintainer's approval.
- **An issue** wakes it on a comment, a label, an assignee, and when it closes.

A watched PR's CI shows on the thread's card while the thread is still working.
