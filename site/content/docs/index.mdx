Frizz runs your coding agents — Claude Code, Codex, and any agent that speaks the Agent Client Protocol — from one browser tab. Every agent that comes to rest needing you becomes a card in one queue, so you work through a list instead of checking on ten terminals.

```bash
npx frizz
```

It brings no model of its own and no workflow of its own. It drives the CLIs you already pay for, under your sign-in, and keeps every opinion it has in a text file you can edit.

## Frizz is for you if

- Terminal UIs feel dated and get in the way of good user experience.
- Orchestrator apps like Conductor feel overly complex.
- Switching between sessions to check on agents is tedious.

## What it does

<Cards>
  <Card title="One queue" href="/docs/queue">
    An agent that needs you becomes a card. Answer it, steer it, snooze it, or mark it done.
  </Card>
  <Card title="Answerable questions" href="/docs/questions">
    Agents ask with lettered options and a recommendation. One keystroke answers.
  </Card>
  <Card title="A board per project" href="/docs/projects">
    One server serves every repo on your machine. Each has its own board, and All projects is a click away.
  </Card>
  <Card title="Headless" href="/docs/threads">
    Each agent runs in its own background process. Close the tab or stop Frizz, and it keeps working.
  </Card>
  <Card title="Threads that talk" href="/docs/handles">
    Every thread has an `@handle`. Agents read, message and wait on each other by it.
  </Card>
  <Card title="Schedules and time limits" href="/docs/schedules">
    "Every weekday at 9am" starts a fresh thread each time. "2h" bounds one.
  </Card>
  <Card title="Your editor" href="/docs/editor">
    Frizz in VS Code, Cursor or Windsurf, with your selection sent along.
  </Card>
  <Card title="From anywhere" href="/docs/remote-access">
    Reach Frizz from your phone with a private frizz.sh name, a tunnel, or Tailscale.
  </Card>

## What it is not

- **Not a model.** Frizz drives the CLIs you already have signed in, on your subscription.
- **Not a cloud.** No account, no telemetry. The server binds `127.0.0.1`, and its state lives in your user directory, never in your checkout.
- **Not a workflow.** No worktrees, branches, or build steps behind your back. A thread behaves like a session you started yourself.
