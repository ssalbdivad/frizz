A sidebar of sessions makes every agent something you have to remember to check on. Frizz gives you one queue instead.

When an agent comes to rest needing you, its thread becomes a card. You read what it did since your last message, then answer its question, steer it, [snooze](/docs/snooze) it, or mark it done. Every action item is in one place, in the order it arrived.

## Only what needs you

The queue is strict about what earns a card, which keeps it a real to-do list. A thread resting only because its own sub-agents are still working, or because it is waiting on CI, a review or a timer, isn't waiting on you. It stays out of the queue until something changes. Nothing shows up just to be dismissed.

## The bands

Every thread is in exactly one of five bands. A project's board names them, and Pinned, Queue and Running never fold.

| Band | What is in it |
| --- | --- |
| **Pinned** | Threads you pinned, whatever they are doing, until you unpin them. |
| **Queue** | Threads at rest that need you, or stopped on a permission prompt. One row per card, each with how long it has waited. |
| **Running** | Threads whose agents are working right now, however long they go quiet. |
| **Snoozed** | Threads you parked, and threads waiting on something outside — a PR, an issue, a timer, the next run of a [schedule](/docs/schedules). |
| **Done** | Threads you marked done. Reply to one to pick it back up. |

## Order

The queue runs oldest first by default, so you cycle through everything; **Settings** can flip it to newest first. A card you are reading never moves under you: new arrivals join the bottom while the page is open.

## Working it

<kbd>j</kbd> and <kbd>k</kbd> walk the cards, <kbd>r</kbd> replies, <kbd>d</kbd> marks done and opens the next, and <kbd>s</kbd> snoozes. See [keyboard shortcuts](/docs/keyboard) for the rest.
